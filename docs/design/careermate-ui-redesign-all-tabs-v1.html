00 五条设计原则

P1
一屏一主操作
每屏只给一个最重要的动作，其余降为次级或藏进详情。消灭「一张卡三个按钮」的选择过载。
P2
诚实的信息
分数必须有量纲和排序意义。满屏「低匹配」既打击用户又无用——要么给档位+归因，要么不显示。
P3
零维护负担
状态尽量由行为自动推断，不让用户维护第二张 Excel（见模型稿 Pipeline 机制）。
P4
渐进披露
卡片只留决策所需的最少信息（公司/岗位/薪资/匹配/命中），细节进详情。降密度。
P5
机会是一等公民
全站围绕「一个求职机会」组织，能力场景（简历/面试/薪资）降为机会内的焦点。

01 导航重构（4 → 5，语义对齐机会）

现状改版理由
机会机会（发现）保留，卡片重构（见 02）
小职小职（对话）保留，改为按机会自动分组的连续会话
面试准备准备（投递看板/工作台）升格为 pipeline 主场：管理所有在办机会，不再是单一「面试」功能
市场（并入）薪资/行情降为「小职内薪资焦点」+ 准备卡片行情提示，不再占独立 tab
—资产（新增）简历版本 · 通用八股题库 · 面试记录，user 级平铺、跨机会复用
我的我的（重构）以「求职画像 + 小职认识你」为主，见 06

最终底栏/侧栏：机会 · 准备 · 小职 · 资产 · 我的。5 个，各自语义单一、互不重叠。

02 Tab 机会 —— 发现岗位

▼ 现状问题

  • 「AI 匹配分 13 / 7」无量纲，满屏「低匹配」——打击用户、且无参考价值
  • 每卡 3 个按钮（分析JD/定制简历/准备面试）选择过载
  • 技能 chip + 命中 + 年限/学历/规模堆砌，密度高
  • 不清楚点了按钮会发生什么、会不会建一堆会话

▲ 改版方案

  • 匹配分归一到 0–100 + 高/中/低档位配色，按分降序；显示「命中 X / 缺 Y」归因
  • 一个主操作「准备这个岗位」（进入该机会的小职），次级仅「收藏」（进暂存区，不建会话）
  • 卡片降密度：公司 / 岗位 / 薪资 / 匹配 / 命中缺失，其余进详情
  • 「分析JD/定制简历/准备面试」不再是卡片按钮，而是进入机会后的焦点

06 Tab 我的 —— 求职画像 + 小职认识你

▼ 现状问题

  • 「我的」易沦为设置堆场，价值感低
  • 求职画像（驱动 AI 匹配的关键）藏得深、不好改
  • A4 长期记忆「小职认识你」缺少可见与纠错入口 → 用户不信任

▲ 改版方案

  • 以求职画像打头（它直接决定机会排序）+ 完整度引导
  • 「小职认识你这些」卡片化，可逐条纠错/删除 → 建立信任与掌控
  • 「在职找工作·隐身模式」显式开关（骑驴找马刚需）
  • 设置收到底部，不喧宾夺主

08 待确认决策点

  1. 底栏 5 个是否偏多？ 可选合并：把「资产」折进「我的」→ 回到 4 个（机会/准备/小职/我的）。推荐先 5 个，资产使用频次高值得独立。
  2. 匹配分口径：0–100 分需要真实可解释的评分模型支撑，否则又是假分数。是否先用「高/中/低 + 命中数」档位、暂不显示精确分？
  3. 「市场」彻底并入是否认可？还是保留一个轻量「行情」入口？
  4. 隐身模式是否本期做（涉及数据可见性策略），还是仅占位、后续实现？
