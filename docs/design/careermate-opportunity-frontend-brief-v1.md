## 1. 搜索交互优化（桌面内联 + 联想，移动端保留全屏）

**现状问题**：点搜索会弹一个 `position:fixed; inset:0` 的全屏遮罩（本是移动端设计），桌面上也弹，导致搜索独占一整屏、体验割裂；且工具条里 `.search-chip` 用了 `flex:1` 会被撑满换行。

**期望**：
- **桌面（≥900px）**：搜索框固定宽度（约 260–320px）留在工具条内，**不弹全屏**；聚焦时在其**正下方浮出联想下拉**（公司 / 岗位分组），「匹配度 / 最新 / 城市」保持在同一行；回车或点选执行搜索，失焦或 Esc 收起。
- **移动端（<900px）**：保留现有全屏搜索遮罩，不动。
- 联想数据复用现有「岗位联想」能力，不用新造。

**验收（Playwright）**：
- 桌面点击搜索：不出现全屏遮罩、搜索框不独占整行；输入时下方出现联想；「匹配度/最新/城市」仍在同一行。
- 移动端点击搜索：仍是全屏搜索。

## 2. 冷启动三档展示（真实产品口径，无假匹配）

后端已按「有无简历」自动切换，前端只需按 `hasResume` 与 `item.unmatched` 渲染对应形态：

**档 1 · 有简历（精准匹配态）**：保持现状——命中 / 缺技能徽章 + 匹配度排序。

**档 2 · 无简历（通用推荐态）**：`item.unmatched === true`
- **不展示匹配环 / 命中缺技能**（没简历不摆假分）。
- 徽章位改为**薪资 / 「最新」标签**。
- 列表顶部放一条友好 CTA 横幅：`📄 上传简历，解锁「命中 / 缺」技能匹配与定制简历` + 「上传简历」按钮。

**档 3 · 纯新用户（无简历且画像无意向）· 冷启动轻问答**：
- 进页先出一张温柔的小卡：「先告诉我们，你想找什么？」
  - **岗位**：输入框 + 联想（combobox，复用「岗位联想」）——自由输入，覆盖全部岗位，**不要用封闭下拉**。
  - **城市**：下拉（来自 §3 的城市接口）。
- 提交后：写入用户画像（调用现有画像保存接口 `targetRole` / `targetCity`），再加载对应城市的机会。
- 底部给条退路：「也可跳过，先看深圳的最新机会」。

> 文案都用鼓励、轻松的语气，别让新用户觉得「必须先填一堆」。

**验收**：
- 无简历用户：无匹配环、有「上传简历」CTA、结果城市=意向/默认城市。
- 纯新用户首访：出现轻问答卡；填岗位+城市后出对应结果；可跳过看最新。

## 4. 全站统一分页组件

抽一个公共分页组件，样式对齐：**第 X–Y 条 / 共 N 条 · 每页 [10 ▾] 条 · ‹ 1 2 3 … N ›**。

- 能力：总数、当前区间、每页条数选择（10 / 20 / 50）、上一页 / 下一页、页码。
- 应用范围：机会页（替换自写的 `.pager`）、资产库、对话历史等现有分页处，统一为同一个组件。
- 移动端：机会页可继续用滚动加载，但复用同一套数据契约（total / page / size）。

**验收**：机会页与资产库分页外观一致；每页切换 10/20/50 生效；「第 X–Y 条 / 共 N 条」显示正确。
