1.1 核心差异：Agent 驱动 vs 用户驱动

❌ 传统应用（用户自己导航）

用户先想清楚要干什么 → 找到对应功能入口 → 手动操作 → 看结果。比如想匹配岗位，用户自己去岗位页搜索。

✅ Agent 应用（Agent 引导流转）

用户说"帮我看看有没有合适的大厂后端岗位" → Agent 自动规划：先检索用户简历 → 调用 RAGForge 搜索 JD 库 → 逐一匹配 → 推荐岗位并列出技能差距 → 建议优化简历 → 生成面试题。

🎯 一句话区分

RAGForge 是"给你一把好用的锤子"（知识检索工具），CareerMate 是"帮你把钉子钉好"（Agent 主动完成求职任务）。
两个项目不重叠，通过 API 协作。

2.2 Agent 驱动的典型流转路径

📍 对话台 ──用户说"帮我分析简历"──→ Agent 规划: 需要简历文件 → ──→ 📝 打开简历工作室
──上传完成──→ Agent 调用 RAGForge 解析简历 → 分析优势/缺失 → ──→ 📍 回到对话台(展示分析结果)
──用户说"匹配大厂后端"──→ Agent 规划: 搜索JD库 → 逐一匹配 → 排序 → ──→ 🎯 打开岗位匹配页(展示结果列表)
──点击字节岗位──→ Agent: 对标JD分析技能差距 → 生成学习建议 → ──→ 📍 回到对话台(展示匹配详情)
──用户说"准备面试"──→ Agent: 检索JD+面题库 → 生成个性化面试题 → ──→ 🎤 打开面试特训
🎯 关键设计：对话台是"家"，其他页面是"工具"

Agent 对话台(P1)是永久的入口和锚点。其他 4 个页面(P2-P5)是 Agent 根据任务需要"推送"给用户的。用户在任何页面都可以一键回到对话台继续对话。 这体现了 Agent 应用的核心体验：用户不需要在菜单栏找功能，Agent 主动带用户到该去的地方。

PART 04Agent 架构设计：规划、工具、记忆

4.1 Agent 核心循环 (Agentic Loop)

用户输入 ──→ ① 观察 (Observe) ──→ ② 规划 (Plan) ──→ ③ 执行 (Act)
执行包括 ──→ 🔧 调用工具 (Tool Call) ──→ 📡 RAGForge API / 📄 文件解析 / 🧮 匹配计算
执行完 ──→ ④ 反思 (Reflect) ──→ ⑤ 回复用户 + 推荐下一步 ──→ 循环 → 用户输入

4.2 工具清单 (Agent Tools)

工具名功能调用时机
search_knowledge调用 RAGForge API 检索知识库任何需要查文档的场景（JD、面题、公司信息）
parse_resume解析上传的简历文件用户上传或更新简历后
match_job简历 vs JD 匹配度计算用户要求匹配岗位时
generate_questions基于简历+JD 生成个性化面试题用户要求准备面试时
evaluate_answer评估用户的面试回答质量用户提交面试回答后
get_dashboard汇总求职数据生成看板用户要求查看进度时
navigate引导用户跳转到特定页面Agent 判断其他页面更适合当前任务

4.3 对话记忆设计

记忆类型内容生命周期
短期记忆当前会话的对话历史、已调用工具、中间结果单次会话
用户画像用户的简历摘要、技能清单、求职偏好、目标公司跨会话持久
任务记忆当前求职任务的进度（已匹配岗位、已完成面试题）跨会话持久
知识缓存高频检索结果的本地缓存（减少 RAGForge API 调用）按 TTL 过期

4.4 页面导航的触发逻辑

用户说什么Agent 推理跳转页面
"帮我看看简历" / "优化简历"需要简历文件 + 分析引擎→ P2 简历工作室
"有什么合适的岗位" / "匹配岗位"需要调用 RAGForge 搜 JD + 逐一匹配→ P3 岗位匹配
"帮我准备XX面试" / "来几道面试题"需要搜 JD + 面题库 + 个性化出题→ P4 面试特训
"最近进展怎么样" / "求职概览"需要汇总所有数据→ P5 求职看板
其他任何问题Agent 尝试在对话台直接回答→ 留在 P1 对话台
